### 개요
OAuth 2.0은 사용자 인증 및 권한 부여를 위한 프로토콜로, 애플리케이션이 사용자 정보를 안전하게 접근할 수 있도록 하는 방법을 제공한다. 주로 웹 및 모바일 애플리케이션에서 사용되며, 사용자에게 자원을 안전하게 공유할 수 있는 메커니즘을 제공한다.

### 기본 원리
OAuth 2.0의 핵심 개념은 클라이언트 애플리케이션이 사용자 정보를 접근하기 위해 직접 사용자 비밀번호를 요구하지 않고, 사용자에게 권한을 부여받아 접근하는 것이다. 이 프로세스는 다음 단계로 진행된다:

1. **사용자 인증**: 사용자가 서비스 제공자(Authorization Server)에 로그인한다.
2. **권한 요청**: 클라이언트 애플리케이션이 사용자의 동의를 요청한다.
3. **토큰 발급**: 사용자가 동의하면, 권한 부여 서버는 클라이언트에게 액세스 토큰을 발급한다.
4. **자원 접근**: 클라이언트는 발급된 토큰을 사용하여 자원 서버(Resource Server)에서 사용자의 자원에 접근한다.

### OAuth 2.0의 주요 구성 요소
1. **Resource Owner**: 자원에 대한 소유자로, 일반적으로 사용자이다.
2. **Client**: 자원에 접근하려는 애플리케이션이다.
3. **Authorization Server**: 사용자의 인증을 수행하고, 클라이언트에게 액세스 토큰을 발급하는 서버이다.
4. **Resource Server**: 클라이언트가 액세스 토큰을 사용하여 자원에 접근하는 서버이다.

### OAuth 2.0 플로우
OAuth 2.0은 여러 가지 플로우를 제공하여 다양한 환경에서 사용할 수 있다. 주요 플로우는 다음과 같다:

- **Authorization Code Grant**: 주로 웹 애플리케이션에서 사용되며, 안전성이 높다. 사용자가 인증 후, 권한 부여 코드가 발급되고, 클라이언트가 이를 사용하여 액세스 토큰을 요청한다.
- **Implicit Grant**: 주로 공개 클라이언트(예: SPA)에서 사용되며, 즉각적으로 액세스 토큰을 받을 수 있지만, 보안이 상대적으로 낮다.
- **Resource Owner Password Credentials Grant**: 사용자 이름과 비밀번호를 직접 사용하여 토큰을 발급받는다. 보안상 취약할 수 있다.
- **Client Credentials Grant**: 클라이언트가 자신의 자원을 접근할 때 사용하는 방식이다. 사용자 인증이 필요 없다.

### 장점
- **보안성**: 비밀번호를 클라이언트와 공유하지 않으므로, 사용자의 자격 증명이 안전하게 보호된다.
- **유연성**: 다양한 클라이언트와 서비스에 적합하도록 설계되어 여러 환경에서 쉽게 사용된다.
- **권한 관리**: 사용자가 클라이언트에게 특정 권한만 부여할 수 있도록 하여, 필요한 최소한의 접근 권한만 허용된다.

### 결론
OAuth 2.0은 현대 웹 및 모바일 애플리케이션에서 사용자 인증과 권한 부여를 처리하는 강력한 프레임워크이다. 이를 통해 사용자 데이터의 안전성을 높이고, 다양한 서비스 간의 안전한 데이터 공유를 가능하게 한다.

자세한 내용은 [RFC 6749](https://datatracker.ietf.org/doc/html/rfc6749)에서 확인할 수 있다.
